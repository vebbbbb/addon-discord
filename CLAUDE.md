# CLAUDE.md: NAVTOK DISCORD for contributors and agents

A WoW Forever addon plus a Windows companion (`NAVTOK.exe`) that post milestones to a Discord
webhook in real time (target: under 2 s), each with a screenshot.

## Hard constraints (do not work around them)

* Addons have **no network** access. SavedVariables reach disk only on `/reload`, logout or
  exit. There is **no combat log** for addons in Forever.
* Target client: Forever beta 1.60.1, `## Interface: 16001`, classic-era API, **Lua 5.1**.
  Bit operations use WoW's `bit` library. No third-party Lua libraries.
* The companion **never** reads game memory, injects anything or sends input to the game.
* Network: only the webhook URL, plus GitHub Releases when the user clicks "Check for
  updates" in the tray (or `self_update` is on, off by default). No telemetry, no listening ports.
* Shipping data (new final bosses): edit Data/Dungeons.lua, tag `vX.Y.Z`; CI publishes
  NAVTOK.exe; players click "Check for updates" (exe swap + restart, addon re-installed).
* The companion writes only `%LOCALAPPDATA%\NAVTOK\{config.json,state.json,navtok.log}` and
  `<client>\Interface\AddOns\NavtokDiscord\`.
* Anything uncertain about Forever goes in **VERIFY.md**; it is never assumed silently.

## Data flow

```
game event -> notifier -> ns.Emit(type, data, {delay, priority})
   -> ring buffer (NavtokDiscordDB.chars["Name-Realm"].events, JSON lines, last 300)
   -> Screenshot queue (1 per minInterval=2 s; full queue drops oldest non-priority;
      level/dungeon/bg are priority and never dropped)
   -> frame N: hide chat (alpha 0) + draw barcode; frame N+1: Screenshot(); frame N+2: hide

WoW writes WoWScrnShot_MMDDYY_HHMMSS.jpg
   -> watcher (fsnotify) -> WaitStable (size settles + JPEG EOI) -> barcode.Decode
   -> event.ParsePayload -> state.Claim -> imageproc.Process -> discord.Sender -> MarkPosted

/reload or logout writes SavedVariables\NavtokDiscord.lua
   -> watcher (debounced 1.5 s) -> savedvars.Events -> not posted and not claimed,
      ts >= installed_at, within late_window_hours, older than SVGrace (8 s)
   -> matcher.Find(shot or ts, ±3 s, screenshots without a decoded barcode)
   -> post "(late)" with or without a picture

plan B (plan_b_band_capture): bandcap polls a corner band at 10 Hz while WoW is the
foreground window -> same decoder -> post without a picture.
```

Never posting twice comes from `state.Claim` (in memory, shared by every path) plus
`state.MarkPosted` (persisted). Claims are released on permanent failure. Transient failures
(offline, 5xx) retry forever with backoff from 2 s to 5 min, and 429 waits for `retry_after`.
A 413 is retried without the image.

## Event data contract

The same names are used in Lua (`Barcode.FIELDS`), Go (`event.fields`) and SavedVariables.

SavedVariables JSON line (sorted keys), produced by `Core.lua` `ns.Emit`:

```json
{"char":"Name","class":"MAGE","classId":8,"data":{...},"id":"<ts>.<seq>","level":60,
 "realm":"Realm","seq":12,"shot":1764160001,"test":false,"ts":1764160000,"type":"loot"}
```

* `id` = `<time()>.<seq>`. `seq` is per character, persisted, and continues across `/reload`.
* `shot` = `time()` when `Screenshot()` was called; used for late matching.
* Dedupe key = `<char>|<id>`.

| type | data fields | trigger | screenshot delay |
|---|---|---|---|
| loot | itemId, quality, count, item | CHAT_MSG_LOOT matched with patterns from LOOT_ITEM_SELF(_MULTIPLE); quality ≥ `lootMinQuality` (4); uncached → GET_ITEM_INFO_RECEIVED, 5 s timeout → link colour | 0 |
| skill | skill, rank | CHAT_MSG_SKILL ~ SKILL_RANK_UP at 75/150/225/300 | 0 |
| level | zone (+ top-level `level`) | PLAYER_LEVEL_UP | 0.5 s, priority |
| reputation | faction, standing (5..8) | UPDATE_FACTION, standingID cached per faction in `char.rep`, posted on increase | 0 |
| death | zone, subzone, killer? | PLAYER_DEAD (ignored for 3 s after login); killer = C_DeathRecap if present, else hostile target or last hostile target | 0 |
| dungeon | encounterId, encounter, instance, bosses, duration, shotSeq | ENCOUNTER_END success: known final boss (`Data.FindFinalBoss`, Forever ids) posts at once. Any other boss kill emits a *candidate* (flag C, `candidate=true`): the companion stores its screenshot (state.json `candidates`, key `<char>#<seq>`) and never posts it. Leaving the instance ALIVE (`char.run`, persisted) with no known final asks via StaticPopup "Did you complete X?"; Yes emits a summary with `shotSeq` = last candidate's seq and the companion posts it with that screenshot. Leaving dead/ghost marks the run `away` (no popup); re-entering continues it; `/navtok done` asks manually | 0.5 s, priority |
| bg | bg, result (win/loss/draw), duration, kb, hk, deaths, honor | UPDATE_BATTLEFIELD_STATUS/SCORE + GetBattlefieldWinner in a pvp instance; once per instance key (persisted in `char.bg.posted`) | ~1 s, priority |
| legacy | achievementId, text, group | ACHIEVEMENT_EARNED for an id in `Data.Legacy` (localized name via GetAchievementInfo; single-zone "Explore X" steps only if `legacyZones`); fallback when the event does not exist: CHAT_MSG_SYSTEM matching `legacyPatterns` | 0 |
| rare | npcId, classification, mobLevel, npc, zone, subzone | rare/rareelite unit (target, mouseover, nameplate) becomes dead and is not tap-denied, or CHAT_MSG_COMBAT_XP_GAIN "X dies..." for a rare seen in the last 120 s; once per GUID | 0 |

Test events (`/navtok test <type>`) set `test=true`. Discord titles get a `[TEST] ` prefix and
late posts a ` (late)` suffix.

## Barcode (summary; the full spec is docs/barcode.md)

* 77 × 13 modules plus a 2-module white quiet zone, 8 physical px per module (648 × 136 px),
  in the top-right corner by default.
* L finder (left column and bottom row solid), clock tracks (top row and right column).
* Frame: `"NV" | ver=1 | len | payload ≤ 96 | CRC-16/CCITT-FALSE` (big endian), row-major,
  MSB first, padded `EC 11`.
* Payload: fields separated by `0x1F`:
  `code, flags, ts, seq, char, classId, level, <type fields>`.
* Drawn on a parentless frame with `SetScale(768 / physicalHeight)`, which makes the pixels
  exact. The decoder measures the grid, so it tolerates other module sizes and scaling.
* **Changing the encoder?** Run `luajit addon/tests/gen_fixture.lua`, then both test suites.
  Bump `VERSION` for any incompatible change.

## Conventions

* Conventional Commits (`feat(addon): …`, `fix(companion): …`, `test:`, `docs:`, `ci:`).
  Commit after each working module.
* Lua 5.1 only: no `goto`, no integer division `//`, no `utf8` library. Use `bit.*`.
  Avoid WoW-only helpers such as `strsplit`, `wipe` and `tinsert`, so the stubs stay small.
  Every handler goes through `ns.On`, which pcall-protects it.
* Each notifier is a `ns.NewNotifier(type)` with `:Init()` (called at PLAYER_LOGIN) and
  `:Test()`. `:Test()` returns sample data, or emits itself and returns nil.
* Register events only via `ns.On`. Unknown events are recorded in `ns.unknownEvents`, not
  raised.
* Go: standard library first. Allowed dependencies: fsnotify, fyne.io/systray, ncruces/zenity,
  x/image, x/sys. Windows-only code lives in `_windows.go` files with a `_other.go` fallback, so
  `go test ./...` runs on Linux.
* Never log or send user data anywhere but the webhook. The User-Agent is generic.
* Tests:
  * `luajit addon/tests/run.lua [filter]`
  * `go test ./...` (the barcode matrix takes about a minute; `-short` runs it at 8 px only)
  * `GOOS=windows go vet ./...` must pass.
